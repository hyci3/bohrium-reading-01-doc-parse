## 1. 已确认的设计决策

1. **核心结果**：将真实科研 PDF 转换为阅读顺序正确、结构边界明确、能够回到原页和原区块的中间文档，再由 Agent 完成具体问答、翻译、提取、核验或知识结构化任务。
2. **主要增量**：重点解决整页按纵坐标排序造成的双栏串行、跨栏元素干扰、跨页续接错误和证据丢失，不平均投入所有增强方向。
3. **实现分工**：环境探测、PDF 探测、坐标提取、阅读顺序、证据编号、结果合并和校验由确定性脚本完成；语义理解、任务作答和必要的视觉复核由 Agent 完成。
4. **能力路径**：优先使用 PyMuPDF；不可用时使用 Poppler `pdftotext` 坐标输出与 `pdftoppm` 页面渲染；OCR 仅作为实际可用时的适配路径。
5. **可移植性**：Skill 内不写本机绝对路径，不依赖当前工作目录，不在正式运行时自动安装依赖；本机 Windows 与 Harbor Linux 通过显式命令参数和能力清单适配。
6. **最小充分实现**：不在 Skill 内放置 README、更新日志、重复安装说明、空目录或与当前流程无关的工具。
7. **短上下文优先**：面向约 256K tokens 名义总上下文，将全量文档留在磁盘，以紧凑索引、确定性证据选择、分段产物和严格工具输出限流支持模型按需阅读。

## 2. 职责与触发边界

### 2.1 Skill 职责

`evidence-pdf-reader` 应在输入科研论文 PDF 且任务需要可靠阅读时触发，覆盖：

- PDF 正文、章节、题注、表格、公式、脚注和参考文献的解析；
- 双栏、多栏和跨栏内容的顺序整理；
- 科研论文的翻译、问答、字段提取、事实核验与知识结构化；
- 需要页码、原文区块、表格或公式定位的科研阅读；
- 扫描页、乱码字体、加密 PDF 等输入的识别、可用路径选择与诚实降级。

### 2.2 最近邻非触发场景

以下请求不应仅因“阅读”或“文档”字样而触发：

- 没有 PDF 或科研材料的一般知识问答、网页摘要和纯文本润色；
- 与科研阅读无关的发票、简历或普通办公文档批量转换；
- 只需单独理解一张图片，而不需要读取 PDF 或其原文证据；
- 只要求文件格式改名、压缩或页面拆分，不要求内容解析；
- 已提供纯文本且用户明确禁止访问原 PDF 的写作任务。

如果用户要求回答科研 PDF 内容，即使只要一个简短答案，也应触发必要的证据链路，而非因为任务简短改用无来源回答。

### 4.2 脚本职责

统一入口为 `python <skill-dir>/scripts/run.py <command> ...`。入口只负责参数解析、调用和退出码，不承载核心算法。

| 模块 | 对应命令或功能 | 核心职责 |
|---|---|---|
| `capabilities.py` | `capabilities` | 探测 Python、PyMuPDF、Poppler、OCR 和 `environment/resources.yaml`；输出工具路径、版本、可用性和首选路径 |
| `case_io.py` | `inspect-case` | 读取真实 `case.json`、`task.md` 和材料，提取 `case_id`、输出契约和输入标识；写早期部分结果 |
| `probe.py` | `probe-pdf` | 检查文件存在性、加密、页数、逐页文字层、图像占比和疑似扫描页，形成处理计划 |
| `extractors.py` | `extract` 的提取层 | 适配 PyMuPDF 或 Poppler，输出统一的页面、词/span、区块和坐标；记录方法与实际失败 |
| `context.py` | `select-context` | 生成紧凑索引，按章节、页码、关键词、区块和预算选择证据；记录 token 估算、累计占用、截断与游标，不生成科学答案 |
| `reading_order.py` | `extract` 的排序层 | 识别跨栏区域、栏位、页眉页脚、题注和跨页候选关系，生成阅读顺序及风险标记 |
| `result_io.py` | 早期结果写入、`finalize-result` | 保留全部原始输出字段，合并 Agent 答案、证据、不确定性和变更记录；采用原子写入 |
| `validators.py` | `evaluate-order`、`validate-result`、`validate-package` | 评估自有样例的阅读顺序，校验 JSON、引用完整性、页码与区块、页面覆盖、状态一致性和资源包限制 |
| `run.py` | 全部命令 | 将 `--work`、输入和输出路径显式传入模块；错误返回非零，不吞掉底层失败 |

### 4.3 开发测试资源

`tests/` 属于开发仓库，不复制到正式 Skill 资源包：

- 单元测试直接使用合成坐标块，不依赖真实 PDF，可稳定复现串栏、跨栏和跨页问题。
- 集成测试使用自建或获授权的 PDF；`fixtures/manifest.json` 记录来源、许可、哈希、测试用途和预期覆盖。
- 生成夹具的脚本仅在开发时使用；目标运行环境不得依赖这些夹具。
- 缺少可选依赖时，测试必须报告明确的跳过原因；核心路径失败不得伪装为跳过或成功。

## 5. 处理架构与数据流

### 5.1 主流程

1. `capabilities`：形成本次真实工具清单，禁止预先声明 PyMuPDF 或 OCR 可用。
2. `inspect-case`：读取输入契约，计算实际输入文件哈希，建立案例目录并在重处理前写早期 `result.json`。
3. `probe-pdf`：逐页判断文字层和处理方式，区分加密、损坏、扫描和混合文档。
4. `extract`：使用选定提取器获得原始坐标信息，再独立执行阅读顺序恢复，避免直接接受工具输出顺序。
5. `select-context`：形成紧凑索引并按任务选择必要证据；禁止默认把完整 `document.json`、原始 bbox 或全部工具日志读入模型。
6. Agent 读取任务和所选证据，完成语义任务；对标记的高风险页使用实际渲染图复核，并控制全案累计原文注入。
7. `finalize-result`：只合并实际答案与有效证据，不自动补写论文未报告的信息；全文献任务合并实际分段产物。
8. `validate-result`：检查契约、证据、页面覆盖、上下文预算、状态和限制；未通过时修复或将状态降级。
9. `validate-package`：提交前检查 frontmatter、文件数量、大小、编码、相对路径和符号链接。

### 5.2 Agent 与脚本的责任分界

| 环节 | 执行者 | 不得越界的行为 |
|---|---|---|
| 工具与 PDF 能力检查 | 脚本 | Agent 不得凭经验声称某工具已安装 |
| 坐标、页码、哈希和结构块 | 脚本 | Agent 不得手工编造边界框、页数或稳定区块编号 |
| 阅读顺序候选与风险检测 | 脚本 | 算法不得在证据不足时静默拼段 |
| 阅读顺序疑难复核 | Agent＋页面渲染 | 不得只看错位文本后按语义猜测原顺序 |
| 上下文索引与切片 | 脚本选择，Agent 给出任务过滤条件 | 不得默认转储完整结构化文档、原始坐标或日志，不得把估算 tokens 写成精确测量 |
| 问答、翻译、提取与知识结构化 | Agent | 不得超出任务和材料，不得把推断写成原文事实 |
| 结果字段与证据引用校验 | 脚本＋Agent | 脚本通过不代表科学含义已获验证，Agent 仍须检查支撑关系 |
| 最终状态 | Agent 决定、脚本检查一致性 | 存在影响主结果的问题时不得保留无保留成功状态 |

## 6. 核心中间数据契约

所有中间 JSON 均包含 `schema_version` 和实际来源；当前规划只约束信息语义，实施时先编写样例再冻结字段。

### 6.1 `capabilities.json`

记录：

- Python 可执行路径和实际版本；
- PyMuPDF 是否可导入及其版本；
- `pdftotext`、`pdftoppm`、`pdfinfo` 和 OCR 的实际路径、版本和能力；
- 本次选择的 `extractor`、`renderer`、`ocr`；
- 每个不可用能力的具体原因和降级影响；
- `environment/resources.yaml` 是否存在及实际解析结果。

工具路径只写入本次 `/app/work` 或本地工作目录中的能力清单，不写入 Skill 源文件。

### 6.2 `case-plan.json`

记录：

- `case_id`、原始 `case.json` 和 `task.md` 路径及 SHA-256；
- 实际 PDF 路径、哈希、文件大小和材料清单；
- 完整保留的原始 `output_contract`；
- 任务要求的工作目录、输出目录和材料边界；
- 缺失输入、契约歧义和路径冲突；
- 早期结果及后续产物的位置。

### 6.3 `pdf-probe.json`

按页记录：

- PDF 物理页码、页面宽高和旋转；
- 可提取字符数、词数、图像情况和扫描页判定；
- 拟采用的提取路径；
- 加密、空白、损坏、OCR 缺失和渲染失败等原因。

判定阈值必须写入配置或代码并可复查，不能将“字符很少”单独等同于扫描页。

### 6.4 `document.json`

基本单位为稳定结构块，至少包含：

| 字段语义 | 要求 |
|---|---|
| `block_id` | 建议 `p0001-b0001`，由物理页和页内稳定顺序生成，重复运行不随机变化 |
| `page_number` | 采用从 1 开始的 PDF 物理页码；印刷页码另存 |
| `bbox` | 统一为 `[x0, y0, x1, y1]`，记录坐标原点、单位和旋转归一化方式 |
| `kind` | 标题、正文、题注、表格、公式、脚注、参考文献、页眉页脚或未知 |
| `text` | 保留实际提取内容；不静默修正科学符号或数值 |
| `reading_order` | 页内和全局顺序分开保存，便于定位排序回归 |
| `extraction_method` | 记录 PyMuPDF、Poppler、OCR 或人工复核标记 |
| `source_fragment` | 必要的原文片段或对应词/span 标识 |
| `warnings` | 坐标歧义、低置信度、可能跨页、无法识别等具体问题 |
| `links` | 跨页续接、题注与图表、公式编号等关系，保留源和目标区块 |

不得为了获得“干净正文”而删除页眉页脚、脚注或低置信度块；它们应与正文分类隔离并保留定位。

### 6.5 `context-index.json` 与 `context-selection.json`

`context-index.json` 是模型首先读取的小规模导航产物，仅包含文档标识、标题、摘要或摘要定位、章节路径、页码范围、图表与公式索引、风险和覆盖状态。不包含全量词坐标、完整工具日志或重复长引文。

每次 `select-context` 生成一个 `context-selection.json`，至少包含：

- 当前任务或过滤条件、选中区块及原阅读顺序；
- `block_id`、物理页码、章节路径和必要原文；
- 单批和全案累计 token 估算，以及 `token_count_method=exact|estimated`；
- 历史非原文交互的实际值或估算值、usage event 来源和未知项；
- 估算方法、安全系数、软上限和剩余预算；
- 是否截断、省略范围、下一批游标及可恢复文件位置；
- 页图选择及其独立预算处理；
- 超预算或证据覆盖不足时的明确警告。

索引和选择结果仍只是证据导航，不能由自动摘要替代关键原文；token 精确值只有在实际使用兼容 tokenizer 时才能标记为精确。

### 6.6 `answer.json`

`answer.json` 是 Agent 按当前任务生成的中间答案，不是预先随包提供的通用论文答案。至少包含：

- 原始输出契约要求的答案字段及实际值；
- 每项关键结论的证据引用，优先引用 `block_id`；
- 直接引文与转述的区分；
- 未报告、无法判断、冲突和不确定性；
- 对翻译或提取任务已覆盖的范围。

### 6.7 `result.json`

- 保留输入中的 `case_id` 和全部原始 `output_contract` 字段，不删除、不改名、不擅自改变类型。
- 写入实际状态、来源、证据、不确定性、限制和变更记录。
- 标准元数据字段与原始契约冲突时，以原始契约为准并停止不安全的自动合并；必须通过显式映射解决，不能覆盖用户字段。
- 发生运行失败时，与材料缺失、无法判断分别记录错误类别。
- 采用同目录临时文件加原子替换，避免中断留下半个 JSON。

## 7. 多栏阅读顺序核心设计

### 7.1 基本原则

- 不直接采用 `pdftotext` 或 PyMuPDF 原始块顺序作为最终阅读顺序。
- 不对整页执行简单的“先纵坐标、后横坐标”排序，因为这会交替读取左右栏。
- 坐标提取、区域检测、栏位检测和跨页续接分开记录，便于单元测试和错误定位。
- 优先保留块和关系，只有证据充分时才合并文本。

### 7.2 页面处理步骤

1. **坐标归一化**：统一页面尺寸、旋转和词/span 到区块的聚合方式。
2. **重复区域识别**：依据跨页重复文本、页面边距和位置识别页眉页脚候选，单独分类保留；首页和奇偶页差异不得被误删。
3. **跨栏元素分区**：识别横向覆盖多个候选栏的标题、图、表和题注，将页面划分为若干垂直区域。
4. **栏位检测**：在每个区域内根据文本行的水平投影间隙、起始位置和列对齐估计栏位；证据不足时回退为单栏并标记，而非强制分两栏。
5. **区块归属**：按区块与各栏的水平重叠比例分配；跨界或重叠不足的区块标记为歧义，进入渲染复核。
6. **区域内部排序**：按“区域从上到下、区域内栏从左到右、栏内块从上到下”生成候选顺序；复杂页面保留替代顺序供复核。
7. **结构分类**：结合编号、字体特征（仅 PyMuPDF 可用时）、文本模式和位置识别标题、题注、公式、脚注与参考文献。
8. **跨页关系**：仅建立有证据的 `continues` 候选关系；不能只因页末没有句号就拼接。保留两个源区块及其全部证据。
9. **风险复核**：对多候选栏序、跨栏歧义、异常小字符、低文字覆盖和任务关键页渲染检查。

### 7.3 可验证输出

每次排序同时保存：

- 原始块顺序和最终块顺序；
- 识别到的区域与栏位边界；
- 每个区块的栏位归属和排序依据；
- 歧义块及替代顺序；
- 被渲染复核的页面及复核结论；
- 跨页关系的源区块、目标区块和建立依据。

这些字段使错误能够定位到“提取、分栏、归属或续接”中的具体一步，而不是只得到一篇无法调试的文本。

## 8. 依赖与降级矩阵

| 能力 | 首选 | 降级 | 不可用时的行为 |
|---|---|---|---|
| PDF 坐标提取 | PyMuPDF | Poppler `pdftotext -bbox` 或可用的 `-bbox-layout` | 无坐标提取器时不声称完成版面恢复，输出明确失败或有限纯文本结果 |
| 页面渲染 | PyMuPDF | `pdftoppm` | 无法渲染时保留文本证据并标记未进行视觉复核 |
| 文档元数据 | PyMuPDF | `pdfinfo` 或可用 PDF 库 | 页数或加密状态未知时限制输出范围并记录原因 |
| 扫描页 OCR | `resources.yaml` 声明工具或经探测确认的 OCR | 无 | 无 OCR 时不猜测文字，标记受影响页为部分完成或失败 |
| 科学符号检查 | 原始 span＋页面渲染 | 坐标文本＋页面渲染 | 无法核对时保留原始字符和不确定性 |
| JSON 与文本处理 | Python 标准库 | 无 | 标准库不满足实现要求时明确报告环境不兼容并非零退出 |

### 8.1 外部命令执行约束

- 使用参数数组，不拼接 shell 命令，不执行 PDF 中提供的任何文本。
- 工具路径来自能力清单，不嵌入用户机器路径。
- 大型输出写入 `/app/work` 或显式 `--work` 下的文件，避免依赖内存捕获全部 stdout。
- 对外部命令设置超时和返回码检查，保存必要错误日志，但不将日志伪称为平台原生轨迹。
- 不在正式运行中执行 `pip install`、自动下载模型或访问未声明服务。

## 9. 状态与失败结构

### 9.1 状态判定

状态取值优先服从原始 `output_contract`。若契约未定义枚举，采用文档化的一致取值，并同时记录机器可读错误类别：

- `success`：任务、证据和契约检查全部完成；
- `partial`：已有可用结果，但存在明确未覆盖页面、字段或子任务；
- `unable_to_judge`：材料可读范围内证据不足，不能形成可靠结论；
- `refused`：输入或限制导致任务不可执行；
- 运行失败通过契约允许的状态或 `errors[].kind = runtime_failure` 表达，不与材料缺失混同。

### 9.2 必须具备的错误类别

`material_missing`、`invalid_contract`、`encrypted_pdf`、`unreadable_pdf`、`extractor_unavailable`、`ocr_unavailable`、`render_failed`、`layout_ambiguous`、`evidence_invalid`、`runtime_failure`、`budget_exhausted`、`context_budget_exhausted`。

任何错误类别都应包含实际阶段、受影响页面或字段、已完成内容和人工接管位置。

## 10. 约 256K tokens 上下文结构

### 10.1 预算层与磁盘层

1. 名义 `context_budget_tokens=256000` 是可配置起点，实际使用时取模型、Harness 和用户约束的最小可用上限。
2. 初始开发配置将全案论文原文与证据注入软上限设为 96,000 tokens，单次证据选择设为最多 24,000 tokens，紧凑索引最多 12,000 tokens，并为系统、工具交互和模型响应保留独立预算。这些是待实测调优值，不是模型能力声明。
3. `document.json`、原始坐标、全量 OCR、渲染页及完整日志只作为磁盘证据层。模型首先接触的是紧凑索引，然后是所选的证据切片。
4. 每个案例在 `work` 中持久化原子更新的预算状态，记录实际进入模型的各批证据、估算方法、累计值、图像数量、主要非原文交互和未处理游标；Agent 在主要请求后通过 usage event 登记实际值或保守估算，不能只计算当前命令的输入长度。

### 10.2 按需选择原则

- 优先契约、章节、页码、字段和确定性关键词过滤，不以额外向量数据库或嵌入服务为必要条件。
- 选择结果按原阅读顺序排列，并保留标题路径、`block_id` 和物理页码。
- 尽量在段落、表格或公式边界截断；不能完整纳入的最小证据单元必须报告，不得静默切成失去科学含义的半句或半个数值。
- 同一证据再次使用时可引用本地游标和已有 `block_id`，不得默认反复粘贴长原文。
- 对问题型任务不进行全文 map-reduce；对翻译或全结构化任务才进入连续分段流程。
- 页图按风险单批限量，未知图像 token 成本不能以文本估算值代替。

### 10.3 全文献任务与耗尽边界

1. 全翻译、全提取和全结构化按章节或连续页段生成实际分段文件，记录输入哈希、覆盖范围和状态，由确定性程序按原顺序合并。
2. 后续段只携带当前原文、必要约束和紧凑术语表，不重复携带此前全部原文、译文和推理。
3. 当前 Agent 无法释放历史上下文时，分段并不等于消除了累计占用；预算将耗尽且必需证据仍未覆盖时，保存续接游标并如实输出部分完成。
4. `select-context` 失败、截断和预算不足不能自动改变原始输出字段，也不能自动把答案降级为无依据摘要。

## 11. 验证结构

### 11.1 三层验证

1. **确定性单元测试**：合成坐标块验证双栏、跨栏标题、页眉页脚、歧义归属和跨页候选；验证输出契约合并与证据引用。
2. **真实 PDF 集成测试**：验证提取器调用、页面覆盖、渲染、结构块、最终 JSON 和异常退出。
3. **Agent 新会话试用**：验证 Skill 被发现并正确触发，完成代表性科研阅读、边界降级和最近邻非触发。

### 11.2 核心通过条件

- 最小合成双栏、跨栏和跨页夹具的阅读顺序与人工标注一致。
- 每个已输出证据引用都能定位到当前文档的有效页和有效区块。
- 原始 `output_contract` 字段覆盖率与 `case_id` 一致性检查通过。
- 跳过页、失败页和未复核页均有记录，不存在静默丢页。
- 无提取器、无 OCR、加密 PDF 和损坏 PDF 均按设计非零退出或写诚实降级结果。
- 同一输入重复运行时，排除时间戳和临时路径后的规范化结构结果一致。
- 正式 Skill 包只含必要的 UTF-8 文本资源，并满足数量、大小和符号链接限制。
- 默认流程不会整体读取 `document.json`；上下文选择遵守单批与全案预算并保留截断、估算方法和续接游标。
- 超过测试软上限的合成文档不会导致无界工具输出；全文献任务能从实际分段文件合并并报告未覆盖范围。

## 12. 不在首版结构中实现的内容

- 完整科学图表语义理解；
- 任意复杂表格、数学公式和扫描论文的全自动高保真恢复；
- 未确认接口的云 OCR 或外部模型服务；
- 平台正式案例、白板、评分或原生轨迹的本地仿造；
- Codex 专用 `agents/openai.yaml`，除非后续出现明确展示或启动需求；
- 自动 GitHub 发布、远程推送或全局安装。

这些边界不影响首版对表格、公式和扫描页进行基础识别、位置保留及明确降级。

## 13. 结构评审结论

该结构以一个统一 CLI、少量单一职责模块和四份按需参考资料形成最小闭环。首版开发应优先打通：

> Poppler 可用路径 → 坐标块 → 双栏排序 → 稳定证据 → 紧凑索引与按需上下文 → Agent 答案 → 合同校验。

PyMuPDF、复杂表格、公式增强和 OCR 均通过同一能力及中间数据接口增加，不能改变早期结果、原始输出契约和证据校验规则；上下文选择同样不得改变这些契约。后续开发计划应以该闭环为主线，避免先铺设全部模块却从未完成端到端可运行结果。
